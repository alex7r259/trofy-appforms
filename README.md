# Trofy AppForms

WordPress-плагин для регистрации экипажей, просмотра заявок и экспорта списка.

## Установка

1. Установить плагин и активировать его.
2. В `wp-config.php` добавить настройки внешней БД **до** `require_once ABSPATH . 'wp-settings.php';`:

```php
define('TROFY_APPFORMS_DB_HOST', 'localhost');
define('TROFY_APPFORMS_DB_USER', 'your_db_user');
define('TROFY_APPFORMS_DB_PASS', 'your_db_password');
define('TROFY_APPFORMS_DB_NAME', 'your_db_name');
```

Пример этих настроек находится в `config.example.php`.

## Шорткоды

- `[event_registration]` — основной shortcode формы, совместимый с текущим шаблоном страницы события.
- `[appforms-301]` — альтернативное имя shortcode формы.
- `[appforms-302]` — защищённый список заявок.

### Привязка к странице события

Если URL страницы события содержит `season_id` и `event_id`, например:

`/news/название-события/?season_id=38&event_id=44`

форма автоматически использует именно эти `season_id` и `event_id`. Это позволяет одному шаблону WordPress обслуживать разные этапы без ручного переключения события в плагине.

После отправки пользователь возвращается на исходную страницу события, а не на жёстко заданный URL `/заявка/`.

## Доступ к заявкам

Пароль задаётся в WordPress → Заявки. Он сохраняется через `wp_hash_password()`. Старый пароль, если он был сохранён в открытом виде, автоматически преобразуется в хеш при первом успешном входе.

После входа выдаётся случайный токен в HttpOnly cookie с ограниченным сроком действия. Сам пароль не передаётся в URL.

## Экспорт

Excel формируется через WordPress `admin-post.php` и защищён:

- администратор — capability `manage_options` + nonce;
- внешний пользователь — действующий защищённый токен доступа.

## Безопасность

Старые standalone-файлы `save.php`, `excel.php`, `settings.php` и `setSave.php` удалены: они содержали отдельные endpoints и/или открытые реквизиты БД.

**Важно:** предыдущая версия репозитория содержала реальные реквизиты БД. Их необходимо сменить на сервере, даже после удаления из текущих файлов, поскольку старые значения остаются в истории Git.

## Важно про схему БД

Плагин ожидает существующие таблицы `appsettings`, `Seasons`, `Events`, `appparticipation` с полями, использовавшимися предыдущей версией плагина. В `appparticipation` поле первичного ключа должно называться `id`, так как оно используется для удаления заявки из админки.
